# ☘️ מועדון הלקוחות של קפה לפריקון

כרטיסייה דיגיטלית שנכנסת ל‑**Apple Wallet** ול‑**Google Wallet** בטלפון של הלקוח.
הברמן/ית סורק/ת את הקוד, הניקוב נוסף, והכרטיסייה בטלפון מתעדכנת תוך שניות — בלי אפליקציה להתקין ובלי כרטיס נייר שמתקמט בארנק.

**החוק:** קונים 8 קפה — התשיעי עלינו. (ניתן לשינוי בקובץ ההגדרות.)

> 🚀 **רוצים להעלות את זה לאוויר ללקוחות אמיתיים?** [**DEPLOY.md**](DEPLOY.md) הוא המדריך המלא ל‑Railway,
> מהתעודות של אפל ועד כרטיסייה שמתעדכנת באייפון. הקובץ הזה מסביר את המערכת עצמה.

## הפעלה מהירה

דרישה יחידה: **Node.js 20 ומעלה** ([הורדה](https://nodejs.org)).

```bash
cd loyalty
npm install
```

צרו מפתח חתימה והדביקו אותו לקובץ ההגדרות:

```bash
npm run secret
```

```bash
cp .env.example .env
```

פתחו את `.env`, הדביקו את ה‑`APP_SECRET` שקיבלתם, וקבעו סיסמת מנהל ב‑`ADMIN_PASSWORD`.
לבדיקה מקומית השאירו `BASE_URL=http://localhost:3000`.

צרו את תמונות הכרטיסייה והפעילו:

```bash
npm run assets
```

```bash
npm start
```

הכתובות יודפסו במסך. רוצים לראות איך זה נראה עם נתונים אמיתיים?

```bash
npm run seed
```

(35 לקוחות והיסטוריה של חודש. למחיקה: `node scripts/seed-demo.mjs --clear`.)

## הגדרת Apple Wallet

> נדרשת חברות ב‑Apple Developer Program — **99$ לשנה**. אין דרך לעקוף את זה; אפל חותמת כל כרטיסייה.

### שלב 1 — רישום סוג כרטיסייה

1. היכנסו ל‑[developer.apple.com/account](https://developer.apple.com/account) → **Certificates, Identifiers & Profiles**.
2. **Identifiers** → כפתור **+** → בחרו **Pass Type IDs** → **Continue**.
3. מלאו:
   * Description: `Leprechaun Coffee Card`
   * Identifier: `pass.co.il.leprechaun.loyalty`
4. **Register**.

רשמו את ה‑**Team ID** שלכם — 10 תווים, מופיע בפינה הימנית העליונה או תחת *Membership details*.

### שלב 2 — יצירת מפתח ובקשת חתימה (CSR)

**בווינדוס** (עם Git Bash, שכולל OpenSSL):

```bash
cd loyalty/certs
openssl genrsa -out pass.key 2048
```

```bash
openssl req -new -key pass.key -out pass.csr -subj "//CN=Leprechaun Cafe\O=Leprechaun Cafe\C=IL"
```

> שימו לב ל‑`//` הכפול ולקווים ההפוכים — זה נדרש ב‑Git Bash בווינדוס. בלינוקס/מק כתבו `-subj "/CN=Leprechaun Cafe/O=Leprechaun Cafe/C=IL"`.

**במק** אפשר גם בלי OpenSSL: *Keychain Access* → תפריט *Certificate Assistant* → *Request a Certificate From a Certificate Authority* → *Saved to disk*.

### שלב 3 — הורדת התעודה

1. חזרו לפורטל → **Identifiers** → לחצו על ה‑Pass Type ID שיצרתם.
2. **Create Certificate** → העלו את `pass.csr` → **Continue** → **Download**.
3. קיבלתם `pass.cer`. המירו ל‑PEM:

```bash
openssl x509 -inform DER -in pass.cer -out pass.pem
```

> אם הורדתם במק וייצאתם מ‑Keychain כ‑`.p12`, אפשר להשתמש בו ישירות — ראו `APPLE_P12_PATH` בקובץ `.env`.

### שלב 4 — תעודת הביניים של אפל

הורידו את **Apple Worldwide Developer Relations Certification Authority (G4)** מ‑[apple.com/certificateauthority](https://www.apple.com/certificateauthority/) והמירו:

```bash
openssl x509 -inform DER -in AppleWWDRCAG4.cer -out wwdr.pem
```

שימו את `wwdr.pem` בתיקיית `certs/`.

### שלב 5 — חיבור להגדרות

ב‑`.env`:

```
APPLE_PASS_TYPE_ID=pass.co.il.leprechaun.loyalty
APPLE_TEAM_ID=ה-Team-ID-שלכם
APPLE_CERT_PEM_PATH=certs/pass.pem
APPLE_KEY_PEM_PATH=certs/pass.key
APPLE_WWDR_PATH=certs/wwdr.pem
```

בדקו שהכול תקין:

```bash
npm run verify
```

הסקריפט קורא את התעודות, בונה כרטיסייה לדוגמה, מאמת את כל גיבובי ה‑SHA‑1 ואת החתימה הדיגיטלית עצמה,
ושומר `tmp/sample.pkpass`. שלחו את הקובץ לאייפון (AirDrop או מייל) — הוא אמור להיפתח ישירות ב‑Wallet.

> **חשוב:** עדכון אוטומטי של הכרטיסייה בטלפון עובד רק כש‑`BASE_URL` הוא **https** עם תעודה תקפה.
> בלוקאלהוסט הכרטיסייה תיפתח, אבל לא תתעדכן לבד.

## הגדרת Google Wallet

> חינם. נדרש חשבון Google רגיל.

### שלב 1 — חשבון מנפיק

1. היכנסו ל‑[pay.google.com/business/console](https://pay.google.com/business/console) → **Google Wallet API**.
2. הירשמו כמנפיק (Issuer) ומלאו את פרטי בית הקפה.
3. העתיקו את ה‑**Issuer ID** — מספר בן 19 ספרות.

### שלב 2 — חשבון שירות

1. [console.cloud.google.com](https://console.cloud.google.com) → צרו פרויקט חדש (או השתמשו בקיים).
2. **APIs & Services** → **Library** → חפשו *Google Wallet API* → **Enable**.
3. **IAM & Admin** → **Service Accounts** → **Create Service Account** (שם: `wallet`).
4. בכרטיסיית **Keys** → **Add Key** → **Create new key** → **JSON** → נשמר קובץ.
5. שימו את הקובץ ב‑`certs/google-service-account.json`.

### שלב 3 — הרשאה למנפיק

חזרו ל‑Google Pay & Wallet Console → **Users** → **Invite a user** →
הדביקו את כתובת המייל של חשבון השירות (מסתיימת ב‑`.iam.gserviceaccount.com`) → תפקיד **Developer**.

### שלב 4 — חיבור ויצירת המחלקה

ב‑`.env`:

```
GOOGLE_ISSUER_ID=המספר-בן-19-הספרות
GOOGLE_SA_FILE=certs/google-service-account.json
```

```bash
npm run google:class
```

הפקודה יוצרת (או מעדכנת) את עיצוב הכרטיסייה אצל גוגל.
**הריצו אותה שוב אחרי כל שינוי במיתוג** — שם, לוגו, כתובת, צבע.

### שלב 5 — פרסום

בהתחלה הכרטיסייה עובדת רק לחשבונות בדיקה שתגדירו בקונסולה.
כשהכול נראה טוב — **Request publishing** בקונסולה. האישור לוקח בדרך כלל כמה ימי עסקים.

> גוגל טוענת את הלוגו מהשרת שלכם, ולכן `BASE_URL` חייב להיות https ונגיש מהאינטרנט **לפני** שמריצים `npm run google:class`.

## העלאה לאוויר

צריך: שרת שרץ ברציפות, דיסק קבוע, ו‑HTTPS.

> **המסלול המומלץ הוא Railway, והוא מתועד במלואו ב‑[DEPLOY.md](DEPLOY.md)** — שם יש את השלבים
> המדויקים כולל התעודות של אפל, משתני הסביבה והמלכודות (Root Directory ו‑Volume).
> מה שכאן הוא לפריסה עצמאית בשרת משלכם.
>
> ⚠️ **Vercel לא מתאים למערכת הזו** — פונקציות serverless בלי דיסק קבוע מוחקות את
> מסד הנתונים, ואי אפשר לפתוח מהן את חיבור ה‑HTTP/2 עם תעודת לקוח שנדרש לדחיפת
> עדכונים לאפל.

### אפשרות א׳ — Docker

```bash
docker compose up -d --build
```

התיקיות `data/`, `certs/` ו‑`backups/` מחוברות החוצה, כך שהנתונים והתעודות שורדים עדכוני גרסה.

### אפשרות ב׳ — שרת לינוקס רגיל

```bash
npm install --omit=dev && npm run assets && npm start
```

מומלץ לעטוף ב‑`systemd` או ב‑`pm2` כדי שהשירות יעלה מחדש אוטומטית.

### HTTPS ו‑Reverse Proxy

הציבו Caddy או Nginx לפני האפליקציה. דוגמה ל‑Caddy — שתי שורות, והתעודה מתחדשת לבד:

```
club.leprechaun.co.il {
    reverse_proxy localhost:3000
}
```

לאחר מכן עדכנו ב‑`.env`:

```
NODE_ENV=production
BASE_URL=https://club.leprechaun.co.il
```

והפעילו מחדש. אם כבר הונפקו כרטיסיות עם כתובת ישנה — הן ימשיכו לפנות אליה, אז עדיף לקבוע את הדומיין הסופי מראש.

### חיבור לאתר הקיים

הוסיפו קישור בתפריט של האתר, והדפיסו QR שמצביע ל‑`https://club.leprechaun.co.il/join` —
על השולחנות, ליד הקופה ובסטורי. בלשונית **מערכת** בדשבורד יש כפתור העתקה לקישור הזה.

## שימוש יומיומי

### פתיחת משתמש לכל ברמן/ית

**ניהול → צוות → הוספת איש/אשת צוות.** או משורת הפקודה:

```bash
npm run staff
```

לכל אחד/אחת משתמש משלו — כך רואים בהיסטוריה מי ניקב מה.
תפקיד **ברמן/ית** נותן גישה לסורק בלבד; **מנהל/ת** — לכל המערכת.

### הסורק

פותחים `https://הדומיין-שלכם/staff/scan` בטלפון של הקופה ומוסיפים למסך הבית (Share → Add to Home Screen) — זה נפתח כמו אפליקציה.

* מכוונים את המצלמה ל‑QR → הכרטיסייה עולה עם צליל ורטט.
* **ניקוב** — מוסיף ניקוב. **ניקוב ×2** — למי שקנה שני קפה.
* סריקה חוזרת תוך 90 שניות מבקשת אישור, כדי שלא ייווצר ניקוב כפול בטעות.
* כשהכרטיסייה מלאה, כפתור הניקוב מוחלף ב‑**מימוש קפה חינם**.
* טלפון מת ללקוח? יש חיפוש לפי שם או טלפון בתחתית המסך.

### ניהול

* **סקירה** — כמה ניקובים היום/השבוע, כמה קפה חינם ניתן, מי הלקוחות הקבועים.
* **לקוחות** — חיפוש, תיקון ניקובים ידני, חסימה, ייצוא לאקסל.
* **צוות** — הוספה, החלפת סיסמה, השבתה.
* **מערכת** — מה מוגדר ומה חסר, מתי פגה תעודת אפל, הקישור להדפסה על QR.

## פתרון תקלות

**הכרטיסייה לא מתעדכנת באייפון**
`BASE_URL` חייב להיות https עם תעודה תקפה. בדקו בלשונית **מערכת** בדשבורד — אם כתוב שם שה‑HTTPS חסר, זו הסיבה.
בדקו גם שהמספר תחת "מכשירי Apple רשומים" בסקירה גדול מאפס; אם הוא 0, אף מכשיר לא נרשם לעדכונים.

**האייפון לא פותח את קובץ ה‑pkpass**
הריצו `npm run verify`. אם הוא עובר עם התעודות האמיתיות שלכם והאייפון עדיין מסרב — בדרך כלל ה‑`APPLE_TEAM_ID` לא תואם לתעודה, או שתעודת ה‑WWDR היא מדור ישן. `npm run verify` יתריע על שתי הבעיות.

**`לא הצלחתי לפתוח את קובץ ה-p12`**
הסיסמה שגויה, או שההצפנה לא נתמכת. הפתרון הפשוט: השתמשו ב‑`APPLE_CERT_PEM_PATH` + `APPLE_KEY_PEM_PATH` במקום ב‑p12.

**Google Wallet מחזירה שגיאת הרשאה**
חשבון השירות לא הוזמן ל‑Issuer בקונסולת Google Pay & Wallet (שלב 3), או שה‑Wallet API לא הופעל בפרויקט.

**המצלמה לא נפתחת בסורק**
דפדפנים מאפשרים מצלמה רק ב‑https (או ב‑localhost). ודאו שנכנסתם דרך הדומיין המאובטח ושאישרתם את הבקשה. תמיד אפשר לעבוד עם החיפוש הידני בינתיים.

**שכחתי את סיסמת המנהל**

```bash
node scripts/create-staff.mjs boss "מנהל חדש" admin
```

**`better-sqlite3` לא מתקין**
צריך כלי בנייה. בווינדוס: `npm install --global windows-build-tools`, או פשוט השתמשו ב‑Docker.

### כמה החלטות שכדאי להכיר

**קוד ה‑QR קבוע ולא מתחלף.** ברקוד בארנק יכול להשתנות רק כששולחים עדכון לטלפון, ולכן קוד מתחלף היה נשבר בדיוק כשאין קליטה. במקום זה הקוד חתום ב‑HMAC (אי אפשר להמציא מספרי כרטיסייה), והשמירה האמיתית היא ש‑`/staff/api/*` דורש התחברות של איש צוות. צילום מסך של קוד לא שווה כלום למי שאין לו משתמש.

**שינוי `APP_SECRET` מבטל את כל הקודים הקיימים.** הוא חותם את ה‑QR. אם משנים אותו, לקוחות יצטרכו לפתוח מחדש את הכרטיסייה. אל תשנו אותו אחרי שעליתם לאוויר.

**ניקוב כפול נחסם רכות.** סריקה חוזרת תוך 90 שניות לא נדחית — היא שואלת. ברמן שבאמת רוצה לנקב פעמיים יכול; טלפון ששהה שנייה יותר מדי מול המצלמה לא יגנוב ניקוב.

**כרטיסייה מלאה לא מקבלת ניקוב נוסף.** צריך לממש קודם. זה מונע מצב שבו לקוח צובר 11 ניקובים ומתווכח כמה קפה חינם מגיעים לו.

**עדכון הארנקים לא מעכב את התור.** הניקוב נשמר ומוחזר מיד; העדכון ל‑Apple ול‑Google נשלח ברקע. אם הוא נכשל — הניקוב הבא מסנכרן מחדש, כי כל עדכון שולח את המצב המלא. תמיד אפשר גם ללחוץ **סנכרון ארנקים** בכרטיס הלקוח.

**כל פעולה נרשמת.** טבלת `events` שומרת מי ניקב, מתי, ובכמה. זה מה שמאפשר להסביר ללקוח למה המונה מראה מה שהוא מראה.

## פקודות

| פקודה | מה היא עושה |
|---|---|
| `npm start` | הפעלת השרת |
| `npm run dev` | הפעלה עם טעינה מחדש בכל שינוי |
| `npm run secret` | יצירת `APP_SECRET` |
| `npm run assets` | יצירת תמונות הכרטיסייה (`--force` לדריסה) |
| `npm run verify` | בדיקת תעודות אפל וייצור כרטיסייה לדוגמה |
| `npm run google:class` | יצירה/עדכון של עיצוב הכרטיסייה בגוגל |
| `npm run staff` | פתיחת משתמש צוות |
| `npm run seed` | מילוי נתוני דמו |
| `npm test` | בדיקת קצה-לקצה מול שרת שרץ (מקומי או ייצור) |
| `npm run pack` | אריזת התעודות למשתני סביבה לייצור |
| `npm run backup` | גיבוי מסד הנתונים |

## החלפת הלוגו

הקבצים ב‑`assets/pass/` הם תמונות ממלאות מקום שנוצרו אוטומטית. להחלפה בלוגו האמיתי שמרו PNG (רקע שקוף עדיף) בשמות:

| קובץ | גודל | איפה זה מופיע |
|---|---|---|
| `icon.png` / `@2x` / `@3x` | 29 / 58 / 87 | התראות ומסך נעילה |
| `logo.png` / `@2x` / `@3x` | 50 / 100 / 150 | ראש הכרטיסייה |
| `hero.png` | 1032×336 | רקע הכרטיסייה ב‑Google Wallet |

אחרי ההחלפה: הפעילו מחדש את השרת, והריצו שוב `npm run google:class` כדי שגוגל תמשוך את הלוגו החדש.
כרטיסיות אפל קיימות יתעדכנו בניקוב הבא.
